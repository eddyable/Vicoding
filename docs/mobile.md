# Building the iOS and Android apps

The mobile apps are the web game bundled offline inside a native shell ([Capacitor](https://capacitorjs.com/)), as decided in [ADR 0001](adr/0001-tech-stack.md). The native projects live in `apps/mobile/ios` and `apps/mobile/android` and are committed; the web build copied into them is not (it's regenerated by `cap sync`).

## What the native app adds over the website

| Feature | Where |
|---|---|
| Works fully offline, including Python for the Final Trial | Web build + self-hosted Pyodide bundled into the app |
| Haptics on victory and failure | `apps/web/src/game/native.ts` (`@capacitor/haptics`) |
| "Come back tomorrow" reminder for the 24-hour trial (FR-53) | `scheduleFollowUp()` (`@capacitor/local-notifications`); tapping it opens the trial |
| App icons | Rendered from one design by `pnpm --filter @vicoding/web icons` |

These native touches are also what keeps the app clear of App Store guideline 4.2 ("minimum functionality"): it isn't a wrapped website.

## Prerequisites

| Platform | You need |
|---|---|
| Both | Node 22+, pnpm 10 (`corepack enable`) |
| iOS | A Mac with Xcode 16+, an Apple Developer account (for TestFlight) |
| Android | Android Studio (Ladybug or newer) with an SDK installed, a Google Play Console account (for internal testing) |

The iOS project uses Swift Package Manager, so CocoaPods is not needed.

## Build and run

```bash
pnpm install
cd apps/mobile
pnpm sync            # builds the web app and copies it into both native projects
pnpm open:ios        # opens Xcode
pnpm open:android    # opens Android Studio
```

Then press **Run** in Xcode or Android Studio to start the app on a simulator or a connected device. Run `pnpm sync` again after every change to the web app.

## Ship test builds

### iOS → TestFlight
1. In Xcode, select the **App** target → *Signing & Capabilities* → choose your team. The bundle id is `app.vicoding.game` (change it in `apps/mobile/capacitor.config.ts` and in Xcode if needed).
2. Choose *Any iOS Device (arm64)* as the destination, then *Product → Archive*.
3. In the Organizer, *Distribute App → TestFlight & App Store → Upload*.
4. In App Store Connect → TestFlight, add internal testers (up to 100, no review needed).

### Android → Play internal testing
1. In Android Studio, *Build → Generate Signed App Bundle / APK → Android App Bundle*, and create an upload keystore. **Keep the keystore and its passwords safe and out of git.**
2. In Play Console, create the app, then *Testing → Internal testing → Create release* and upload the `.aab`.
3. Add testers by email list and share the opt-in link.

For quick side-loading on a single Android phone, *Build → Build APK(s)* produces a debug APK you can install directly.

## Notes

- **Notifications:** the app asks for permission only when the player taps "Remind me tomorrow". Android 13+ shows the system prompt then; the required permissions come from the plugin's manifest.
- **App size:** about 15 MB, mostly Python for the Final Trial.
- **Updating icons:** edit the design in `apps/web/scripts/render-icons.mjs`, run `pnpm --filter @vicoding/web icons`, then `pnpm sync`.
- **Service worker:** registered only on the web; the native app is already offline.
